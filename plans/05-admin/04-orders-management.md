# Керування замовленнями

## Список (`/admin/orders`)

Таблиця: номер, клієнт (username/ім'я), сума, статус, оплата, дата. **Фільтри — саме те, що просив користувач ("список, що оплачено, чи не оплачено")**:

- За `status` (chips: Усі / Нові / Підтверджені / Відправлені / Завершені / Скасовані)
- За `payment_status` (Усі / Оплачено / Не оплачено)
- За датою (сьогодні / 7 днів / діапазон)
- Пошук за номером замовлення чи телефоном клієнта

Реалізація фільтрів — query params (`?status=pending&payment=unpaid`), запит на сервері комбінує `.eq()`/`.in()` умовно, як у `04-miniapp/02-catalog-and-filters.md`.

## Деталі замовлення (`/admin/orders/[id]`)

- Товари (з `order_items`), контакти клієнта, адреса доставки.
- Кнопки зміни статусу — тільки валідні наступні переходи показані (`pending → confirmed`, `confirmed → shipped`, `shipped → completed`, будь-який нетермінальний → `cancelled`).
- Перемикач "Оплачено" (`payment_status`) — окремо від статусу доставки.
- Поле `admin_note` — для ТТН Нової Пошти, причини скасування тощо.
- Кнопка "Написати клієнту" — deep-link `https://t.me/{customer.username}` якщо є username.

## PATCH-обробник

`PATCH /api/admin/orders/[id]` — приймає частковий `{ status?, payment_status?, admin_note? }`, валідує допустимість переходу статусу (мапа дозволених переходів у `lib/validation/order.ts`), оновлює рядок, і **якщо `status` змінився** — викликає `notifyCustomer` з відповідним текстом (`03-bot/03-notifications.md`).

## Оптимістичний UI

TanStack Query `useMutation` з `onMutate` — статус у таблиці міняється миттєво, відкат при помилці сервера (`onError` → `queryClient.setQueryData` назад).
