# Онлайн-оплата (post-MVP)

MVP: оплата "при отриманні" або переказом, адмін вручну тисне "Оплачено" в `/admin/orders/[id]` → `payment_status = paid`. Таблиця `payments` вже готова приймати транзакції, коли дійде черга до провайдера.

## Коли додавати провайдера

Найпростіші варіанти для укр. e-commerce: **LiqPay** (Приватбанк, checkout-віджет або redirect) або **Monobank Acquiring** (простий REST API). Обидва дають webhook на підтвердження оплати.

## Інтеграційна точка (вже закладена в схему)

`POST /api/payments/webhook/[provider]`:
1. Перевірити підпис вебхука провайдера (кожен має свій метод — LiqPay: `data + signature` SHA1, Monobank: `X-Sign` ECDSA).
2. `insert payments` з `raw_payload` (аудит).
3. Знайти `order_id` за `external_id`/референсом.
4. `update orders set payment_status = 'paid' where id = ...`.
5. `notifyCustomer` — "Оплату отримано".

## Чому не зараз

Користувач у поточному запиті прямо не просив миттєвої інтеграції платіжного шлюзу — фокус на самій вітрині/боті/адмінці. Додавання платіжного провайдера вимагає реєстрації мерчант-акаунта (окрема дія користувача поза Claude Code), тому винесено в post-MVP з готовою точкою розширення.
